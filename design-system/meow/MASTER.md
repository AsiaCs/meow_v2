## 0. Product

meow is a live index of AI and tech networking events and internships, scraped from
Luma and Cerebral Valley every 30 minutes, filtered by city, aimed at early-career
technical people. The product's asset is the data itself, which is why the design
system treats real listings as the primary visual rather than reaching for staged
screenshots or stock photography.

Platform: web. Next.js 16 App Router, React 19, Tailwind CSS v4 (CSS-first, theme
lives in `app/globals.css`). Supabase auth, Prisma, Stripe.

## 1. Dials

| Dial | Value | Why |
|---|---|---|
| `DESIGN_VARIANCE` | **6** | The asymmetric split hero is genuinely load-bearing and stays. Not higher, because the audit found decoration masquerading as variance (thirteen eyebrow labels, a colophon strip) rather than real compositional risk. |
| `MOTION_INTENSITY` | **4** | Consumer surface seen repeatedly, so the frequency gate applies: entrance reveals and hover states, one scroll-driven sequence, nothing choreographed. |
| `VISUAL_DENSITY` | **5** | It is a real index. Listing rows have to be dense enough to scan and loose enough to read at 15px. |

## 3. Colour — "Let's Be Thinkers" (HAUS)

Five source swatches, locked:

| Swatch | Role in this system |
|---|---|
| `#1C3334` deep teal-black | base surface family |
| `#2F4454` slate blue-gray | secondary surface family (shaded to `#21303B` to join the ladder) |
| `#2E151B` deep maroon-black | deepest / inverse surface, and the ink on rose fills |
| `#DA7B93` dusty rose | **primary accent** |
| `#376E6F` muted teal | secondary accent, fills and borders only |

**Three measured facts that constrain every component:**

1. White on `#DA7B93` is **2.90:1**. There is no white-on-rose button in this system;
   labels on a rose fill use the maroon (`--on-brand`, 5.84:1).
2. `#376E6F` is **2.00:1** against the rose and under 3:1 against every base. It is
   never text. It is a fill and a border.
3. The three dark swatches sit within **1.67:1** of each other, so surfaces cannot
   separate by fill. Depth is carried by hairlines and by the grain, never by shadow.

**Dark is the default.** The source palette has no light neutral, so light mode is a
derived translation: inks are the maroon deepened, surfaces are the rose mixed toward
white. Never pure `#fff`.

Full token table lives in `app/globals.css`. Measured worst-case contrast, across every
surface in each mode:

| | dark | light |
|---|---|---|
| text-primary | 9.33:1 | 13.81:1 |
| text-secondary | 5.46:1 | 7.82:1 |
| text-muted | 4.86:1 | 5.52:1 |
| brand-text | 5.57:1 | 4.80:1 |
| positive / critical / warning / info | 4.60–5.70:1 | 4.76–4.97:1 |
| on-brand on rose fill | 5.84:1 | 4.91:1 |

`--color-text-disabled` sits at 2.74:1 **on purpose**. WCAG 1.4.3 exempts inactive
controls, and a disabled control that meets contrast does not read as disabled. It
never carries content.

## 4. Typography

Two voices, both from the approved shortlist. There is no third mono voice.

| Role | Face | Why |
|---|---|---|
| Display, wordmark | **Sora** (100–800, variable) | Enough weight range for the wordmark and the display scale, enough irregularity to survive heavy negative tracking without reading as a default geometric sans |
| UI, body, numerals | **Public Sans** (400/500/600/700) | Drawn for dense service interfaces, which is the job: 13–15px listing rows on a dark ground. Ships tabular lining figures |

The previous system carried IBM Plex Mono purely so figures aligned between rows.
Public Sans does that with `font-variant-numeric: tabular-nums`, and dropping the third
family also removed the uppercase-mono-label texture that was appearing above every
section heading.

Emphasis inside a headline is **italic of the same family** (`.u-emphasis`), never a
second family dropped into the middle of a line.

Scale: `display-xl / display-l / display-m / heading-l / heading-m / body-l / body-m /
label / meta`, each with explicit size, leading and tracking. Arbitrary `text-[Npx]` is
a bug; the audit found 58 of them.

## 5. Radius

**Three values, one rule.** The audit found sixteen in circulation.

| Token | Value | Applies to |
|---|---|---|
| `--radius-pill` | 999px | buttons, filter chips, tabs |
| `--radius-panel` | 14px | cards, inputs, sheets, sidebar |
| `--radius-inset` | 8px | anything nested inside a panel, and the focus ring |

## 6. Motion

- Entrances are CSS `@starting-style` (`.enter`, `.enter-row`), so content is visible
  without hydration and a failed animation degrades to "no animation", never to
  "no content".
- The easing is a real spring encoded as `linear()`, including overshoot.
- One scroll-driven sequence on the site (the week pan), progressively enhanced: the
  default is a plain horizontal scroll that works with no JS.
- **`prefers-reduced-motion` is handled twice**: a global CSS backstop, and an explicit
  `useReducedMotion()` branch in every JS-driven component. The backstop cannot reach a
  JS transform, which is how the closing CTA was animating regardless of the setting.

## 7. Icons

**Phosphor only**, one weight per context. No hand-rolled icon paths, no emoji as UI.

Server components must import from `@phosphor-icons/react/dist/ssr`. The package's
main entry is a client component, and importing it into a server page fails the build
with `createContext is not a function` during static generation. Client components use
the main entry as normal.

`lucide-react` has no importers left and can be removed from package.json.

The only hand-rolled SVGs in the app are third-party brand marks (Google, Outlook),
which no icon library carries and which must stay exact.

## 8. Do not produce

Harsh gradients · Lucide by reflex · pure white backgrounds · rainbow colour · drop
shadows as ambience · three-equal-feature-cards · emoji as decoration · glassmorphism ·
em dashes in UI copy · Inter/Geist/Space Grotesk as the only safe font · colored
left-stripe callouts · fake testimonials · reflexive bento grids · terminal-window
graphics · "it's not X, it's Y" copy · checkmark bullets by default · three pricing
tiers · no real product demo · one corner radius on everything · purple-and-black ·
missing loading states · radial gradient orbs · dot-grid backgrounds · sparkle icons ·
animated arrows · missing ToS · missing Privacy · purposeless hover animation · neon ·
lazy pastels.

Plus, from the audit of this specific codebase: section-numbering micro-meta
(`№ 999 / Colophon`), an uppercase tracked eyebrow above every section heading (budget
is one per three sections), and two different labels for the same CTA intent.


## 9. Figma design track (added after the code rollout)

An additive, exploratory design track running in parallel with the codebase. It does not
supersede anything in sections 0 through 8, and it does not change application code:
the HAUS rollout already in `app/` stays exactly as shipped. Work moves from Figma into
code only when explicitly requested, one approved piece at a time.

**Sequence, and it is a gate not a suggestion:** Foundations brand board → sign-off →
Components → Screens. Fixing the foundation after screens exist is expensive; before,
it is free.

### Where the Figma work lives, and why

The Foundations file sits in the **Santa Clara Unified School District** organisation
(Enterprise), not in the personal Starter team where it started. It was moved there on
2026-08-30 because the Starter plan's limits made the work impossible.

| Limit | Starter | Enterprise |
|---|---|---|
| MCP tool calls | **20 per month** | 600 per day |
| Variable modes per collection | 1 | unlimited |
| Pages per file | 3 | unlimited |

The Foundations board alone consumed all 20 Starter calls, including two repairs and
four validation screenshots. Budget roughly one call per board section when planning.
Only `whoami`, `create_new_file` and `add_code_connect_map` are exempt from the count;
`use_figma` and `get_screenshot` both spend one.

**Two caveats attach to that org, and they are not hypothetical.** The district
administers those files: their IT can view, audit, transfer or delete them, and the
files go away if the account is deprovisioned. meow is a live commercial product, so
if this design system ever matters beyond exploration, it belongs somewhere the product
owner controls. This was raised and the move was made deliberately.

**Moving a file from a personal team into an org is not a "Move to project" operation.**
Figma blocks that direction. The route that works is File → Save local copy (`.fig`),
then Import into the destination project. That preserves pages, frames, variables and
node IDs, but mints a **new file key**, so any recorded URL must be updated.

### Two API limits that are not plan-related

- `figma.root.name` cannot be set. File renames are always a manual step, and a `.fig`
  import lands as "Untitled" regardless of the source file's name.
- Figma projects (folders) cannot be created through the MCP. The user makes them in
  the UI.

### Connection requirement

The remote server (`https://mcp.figma.com/mcp`) is preferred over the desktop variant:
it supports writing native Figma content (frames, components, variables, auto layout),
not only reading existing designs. The desktop variant is read-weighted.

Note that a server configured in `~/.claude.json` is an **MCP server, not a plugin** — it
appears under `/mcp`, not under `/plugin`'s Installed tab. MCP servers are connected at
session start, so a server added mid-session does not appear until the session restarts.

The capability is two-way. This track uses the write direction (system → Figma). The
read direction (Figma → code) exists but is not a round-trip: bring pieces back
deliberately and individually, never in one pass.

### Three Figma quirks worth knowing before editing these

1. **`combineAsVariants` resets paint opacity to 1.** Any tint applied to components
   before combining is silently lost. Apply tints to the variants afterwards. This bit
   both Button/Danger and the three tinted Badge variants.
2. **`setBoundVariableForPaint` returns a frozen paint.** Passing `opacity` in the
   input object does not survive. Clone the returned paint and set opacity on the clone.
3. **`createInstance()` can capture a fill override** instead of inheriting. There is
   no per-property override reset, so copy the main component's fills onto the instance.

### Icons are absent, deliberately

No icon library is added to this file. The code uses Phosphor, and hand-drawing glyphs
is banned by the system's own rules. The Sidebar item ships a placeholder frame named
`Icon`, ready for INSTANCE_SWAP once the Phosphor Figma library is added.

### Guardrails

- Nothing in Figma is shipped by virtue of existing there.
- Canvas writing is beta: verify what actually landed after every write.
- Selection-based work only, one frame or one small flow at a time.
- Prompts reference the Foundations file rather than restating the system.
- An off-system value wanted by a screen is a Foundations gap: add it there with
  sign-off first, never inline on the screen.
